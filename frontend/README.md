# Тихо — frontend

Тёмный адаптивный интерфейс к существующему Go API. Без сторонних JS-зависимостей, сборки, внешних шрифтов и аналитики. Нужен Node.js 18 или новее.

## Запуск

1. В корне проекта запустите БД и Go-приложение вашим обычным способом (`make run`). Для локального HTTP в окружении бэкенда нужен `COOKIE_SECURE=false`.
2. В другом терминале:

   ```sh
   cd frontend
   npm run dev
   ```

3. Откройте **http://localhost:5173**. `npm install` не нужен.

Dev-сервер привязан к loopback и обслуживает только frontend-файлы. Запросы `/api/*` проксируются на `http://127.0.0.1:8080`. Браузер работает с одним origin, поэтому cookie-сессии и существующая CSRF-защита работают без CORS-изменений в Go. `Host`, `Origin` и `Sec-Fetch-Site` сохраняются для проверок. Dev-прокси не предназначен для публикации в интернет.

При другом адресе API или занятом порте:

```sh
API_TARGET=http://127.0.0.1:8081 FRONTEND_PORT=5174 npm run dev
```

## Что работает

- Регистрация и отдельный вход; восстановление пользователя через `/me`.
- Создание счетов и отображение вычисленных сервером балансов.
- Доходы, расходы, внутренние переводы, выбор даты и описание.
- История: тип операции, счёт, страницы по 20 записей.
- Удаление с подтверждением и обновлением балансов.
- Выход, обработка истёкшей сессии, недоступного API и пустых списков.
- Явный деморежим: пример данных только в памяти вкладки, без запросов записи в API.

Суммы вводятся в рублях и передаются API целыми копейками. Дата вводится в местном времени браузера и отправляется в ISO UTC. Общий баланс относится ко всем счетам, а не к выбранной странице истории. Токен остаётся в HttpOnly-cookie: frontend не читает его и не хранит в localStorage. При выходе очищается состояние интерфейса.

Сейчас поддерживается числовой диапазон JS safe integer: суммы вне диапазона не принимаются и не отображаются как точные. Для идентификаторов вне этого диапазона потребуется согласовать с API строковое представление.

## Проверка

```sh
npm run check
```

Ручной сценарий: регистрация → вход → два счёта → доход/расход/перевод → фильтры → удаление → выход. Повторный вход должен восстановить данные с API. Проверьте также мобильную ширину, Tab/Escape в диалогах, отсутствие сессии и выключенный API.

Для production понадобится HTTPS и раздача этих статических файлов вместе с `/api/` под одним origin через reverse proxy; `COOKIE_SECURE=true`. Эта локальная версия не публикует и не изменяет бэкенд.
